> **Type:** Multiple choice · **Difficulty:** Easy · **Points:** 1 · **Tags:** `f26-w3`, `interrupts`, `flag-enable`

#### Question

Which statement correctly distinguishes an interrupt **flag** from an interrupt **enable** on the PIC16F883?

- A. The flag records that the event/request occurred; the enable controls whether that request can reach interrupt service.
- B. The enable records that the event occurred; the flag selects the interrupt priority.
- C. The flag and enable are two names for the same bit.
- D. The flag saves W while the enable saves STATUS.

#### Key

**Answer:** A. The flag records that the event/request occurred; the enable controls whether that request can reach interrupt service.

**Why:** The durable model is event -> flag -> enable gates -> CPU interrupt entry. A flag can record an event even when the corresponding interrupt is masked.

**Correct feedback:** Correct. Think event/request versus permission to interrupt.

**If incorrect:** Separate the hardware event from the permission gate: the flag records the request and the enable controls whether it can cause service.

### `pic.interrupts.w03.002`

> **Type:** True/false · **Difficulty:** Easy · **Points:** 1 · **Tags:** `f26-w3`, `interrupts`, `flags`

#### Question

An interrupt source flag can become set while its individual interrupt enable or `GIE` is clear.

- True
- False

#### Key

**Answer:** True

**Why:** The flag records the event/request independently of whether the request is currently allowed through the interrupt-enable gates. This is why stale flags matter before enabling interrupts.

**Correct feedback:** Correct. Masking the interrupt request does not necessarily prevent the hardware event flag from being set.

**If incorrect:** The event flag and the enable gate are separate. A pending flag can exist while service is masked.

### `pic.interrupts.w03.004`

[Back to this question](../rcet3373-w03-interrupts.md#q-pic-interrupts-w03-004)

> **Type:** Multiple choice · **Difficulty:** Easy · **Points:** 1 · **Tags:** `f26-w3`, `interrupts`, `entry`

#### Question

Which state is automatically saved by PIC16F883 hardware when an interrupt is accepted?

- A. The return program counter on the hardware stack
- B. W and STATUS in common RAM
- C. Every SFR used by main
- D. The active interrupt source flag

#### Key

**Answer:** A. The return program counter on the hardware stack

**Why:** Interrupt entry pushes the return PC onto the hardware stack and vectors execution to `0x0004`. W and STATUS are not automatically preserved for the program by this mechanism.

**Correct feedback:** Correct. The return PC is automatically stacked; other processor context may require software preservation.

**If incorrect:** Do not confuse the hardware return stack with software context storage. The device automatically stacks the return PC.

> **Type:** Multiple choice · **Difficulty:** Easy · **Points:** 1 · **Tags:** `f26-w3`, `interrupts`, `retfie`

#### Question

What does `RETFIE` do that an ordinary `RETURN` does not?

- A. It returns from the interrupt and re-enables global interrupts by setting `GIE`.
- B. It automatically clears every interrupt source flag.
- C. It saves W and STATUS before returning.
- D. It resets the hardware stack.

#### Key

**Answer:** A. It returns from the interrupt and re-enables global interrupts by setting `GIE`.

**Why:** `RETFIE` returns using the stacked PC and sets `GIE`. If the source request is still pending, re-enabling interrupts can lead directly back into service.

**Correct feedback:** Correct. The source condition must already be serviced correctly before `RETFIE` re-enables interrupt acceptance.

**If incorrect:** `RETFIE` is an interrupt return, not a generic flag-clearing or context-saving instruction.

#### Question

Place these ISR responsibilities in a safe conceptual order for the PIC16F883 single-vector model.

**Put these in order:** Execute RETFIE; Identify the requesting source from its flag(s); Restore the saved processor context; Save required processor context; Service the source and leave its request condition resolved

1. ______________________________
2. ______________________________
3. ______________________________
4. ______________________________
5. ______________________________

#### Key

**Answer:** Save required processor context → Identify the requesting source from its flag(s) → Service the source and leave its request condition resolved → Restore the saved processor context → Execute RETFIE

**Why:** A robust single-vector pattern is save context -> identify source -> service/clear -> restore context -> `RETFIE`. Multiple source handlers can funnel to one common restore/exit path.

#### Question

An ISR services `RB0/INT` but returns with `INTF = 1`. `INTE` is still set. What is the most likely behavior once `RETFIE` sets `GIE` again?

- A. The interrupt request can immediately send execution back through interrupt entry because the source is still pending.
- B. The processor ignores `INTF` until Reset because the ISR has already run once.
- C. `RETFIE` automatically clears `INTF`, so nothing unusual occurs.
- D. The return PC is lost because the flag is still set.

#### Key

**Answer:** A. The interrupt request can immediately send execution back through interrupt entry because the source is still pending.

**Why:** The source condition must be resolved before the common exit. With `INTF`, `INTE`, and restored `GIE` all active, the CPU can immediately re-enter interrupt service.

**Correct feedback:** Correct. A pending enabled request can be serviced again as soon as global interrupt acceptance is restored.

**If incorrect:** Trace the request path after `RETFIE`: source flag still set + source enable set + GIE restored means the request is still eligible.

#### Question

At `FOSC = 4 MHz`, the external-interrupt latency is 3 to 4 instruction cycles. What is the **maximum** nominal latency in microseconds?

_Numeric response in us._

#### Key

**Answer:** 4 us

**Why:** `FCY = 4 MHz / 4 = 1 MHz`, so `TCY = 1 us`. The maximum of the stated 3-4 cycle latency is `4 * 1 us = 4 us`.

**Correct feedback:** Correct. At 4 MHz, one instruction cycle is 1 us, so four cycles is 4 us.

**If incorrect:** First calculate `FCY = FOSC/4`; at 4 MHz that gives a 1 us instruction cycle. Then use the upper end of the 3-4 cycle latency range.

## Interrupt Context Saving

<a id="key-pic-context-w03-001"></a>
### `pic.context.w03.001`

[Back to this question](../rcet3373-w03-interrupts.md#q-pic-context-w03-001)

> **Type:** Multiple choice · **Difficulty:** Medium · **Points:** 1 · **Tags:** `f26-w3`, `interrupts`, `context`, `common-ram`

#### Question

Why is common RAM such as `0x70-0x7F` useful for temporary interrupt context storage on the PIC16F883?

- A. The same common RAM addresses are accessible without first depending on a particular bank selection.
- B. Common RAM is part of the hardware return stack.
- C. Values in common RAM are automatically restored by `RETFIE`.
- D. Only interrupt code can access common RAM.

#### Key

**Answer:** A. The same common RAM addresses are accessible without first depending on a particular bank selection.

**Why:** Using common RAM for `W_TEMP`/`STATUS_TEMP` avoids needing to change bank state merely to reach the temporary storage locations while the original STATUS is being preserved.

**Correct feedback:** Correct. Context save code should avoid creating a bank-selection dependency before the original STATUS has been preserved.

**If incorrect:** Common RAM is ordinary data memory, not the return stack and not automatically restored. Its useful property here is bank-independent accessibility.

### `pic.context.w03.002`

[Back to this question](../rcet3373-w03-interrupts.md#q-pic-context-w03-002)

> **Type:** Multiple choice · **Difficulty:** Medium · **Points:** 2 · **Tags:** `f26-w3`, `interrupts`, `context`, `swapf`

#### Question

Why does the Microchip context-save pattern use `SWAPF` while preserving/restoring STATUS instead of relying on `MOVF STATUS,W`?

- A. `SWAPF` can move the value without changing STATUS flags, while `MOVF` can affect Z before STATUS is safely preserved.
- B. `SWAPF` automatically pushes STATUS onto the hardware stack.
- C. `MOVF` cannot read STATUS.
- D. `SWAPF` disables interrupts until `RETFIE`.

#### Key

**Answer:** A. `SWAPF` can move the value without changing STATUS flags, while `MOVF` can affect Z before STATUS is safely preserved.

**Why:** The temporary swapped form is a means of transferring/restoring the value without modifying STATUS flags during the save/restore sequence. The later swap restores the original nibble order.

**Correct feedback:** Correct. The save/restore sequence must avoid changing the very status bits it is trying to preserve.

**If incorrect:** Inspect the instruction effects: `MOVF` can affect Z, while `SWAPF` is useful in this sequence because it does not alter STATUS flags.
